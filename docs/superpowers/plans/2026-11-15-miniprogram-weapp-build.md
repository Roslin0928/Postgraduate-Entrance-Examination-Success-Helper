# 小程序微信端构建链 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为现有 Taro React 小程序源码增加可重复的微信端开发/生产构建命令，并生成可导入微信开发者工具的 `dist` 产物。

**Architecture:** 在 `apps/miniprogram` 内补齐 Taro 4 CLI、Webpack 5 runner、React framework plugin 和微信平台 plugin；通过 `config/index.ts` 固定 source/output 目录和微信平台，沿用源码中的 `TARO_APP_API_BASE_URL` 环境变量。后端 API、页面源码和业务接口保持不变，生成的 `dist` 目录由 Git 忽略。

**Tech Stack:** Taro 4.1.5, React 18, TypeScript, Webpack 5, 微信小程序平台。

**Spec:** `docs/superpowers/specs/2026-11-15-miniprogram-weapp-build-design.md`

## Global Constraints

- Node.js 20+；项目包管理器固定为 `pnpm@9.15.4`。
- Taro 相关新增依赖统一固定为 `4.1.5`，避免 CLI、runner 和插件版本漂移。
- API 默认地址必须保持 `http://localhost:3000`；只有设置 `TARO_APP_API_BASE_URL` 时才覆盖它。
- 不修改现有页面、后端接口、Prisma schema、登录流程或 `.env` 中的密钥。
- 不提交 `apps/miniprogram/dist`、`node_modules`、`.env` 或数据库文件。

### Task 1: 安装并固定 Taro 微信构建依赖

**Files:**
- Modify: `apps/miniprogram/package.json`
- Modify: `pnpm-lock.yaml` (generated by pnpm)

**Interfaces:**
- Produces the `taro`, `taro build --type weapp`, and `taro build --type weapp --watch` commands used by Task 2 and Task 3.

- [ ] **Step 1: Add the exact Taro 4.1.5 packages**

Run from the repository root:

```powershell
pnpm.cmd --filter miniprogram add -D `
  @tarojs/cli@4.1.5 `
  @tarojs/webpack5-runner@4.1.5 `
  @tarojs/plugin-framework-react@4.1.5 `
  @tarojs/plugin-platform-weapp@4.1.5
```

The command must update only `apps/miniprogram/package.json` and `pnpm-lock.yaml`.

- [ ] **Step 2: Add the build scripts**

In `apps/miniprogram/package.json`, preserve the existing `build` and `lint` scripts and add:

```json
"dev:weapp": "taro build --type weapp --watch",
"build:weapp": "taro build --type weapp"
```

- [ ] **Step 3: Verify the dependency boundary**

Run:

```powershell
pnpm.cmd --filter miniprogram exec taro --version
```

Expected: the command exits successfully and reports a Taro 4.x CLI version.

- [ ] **Step 4: Commit the dependency change**

```powershell
git add apps/miniprogram/package.json pnpm-lock.yaml
git commit -m "build: add taro weapp toolchain"
```

### Task 2: Add Taro configuration and WeChat project root

**Files:**
- Create: `apps/miniprogram/config/index.ts`
- Modify: `apps/miniprogram/project.config.json`

**Interfaces:**
- Consumes: the `src` directory and the `TARO_APP_API_BASE_URL` environment variable referenced by existing pages.
- Produces: a Taro configuration with `sourceRoot: "src"`, `outputRoot: "dist"`, React framework, Webpack 5 compiler, and `weapp` target support.

- [ ] **Step 1: Create the minimal Taro configuration**

Create `apps/miniprogram/config/index.ts` with:

```ts
import { defineConfig } from '@tarojs/cli';

export default defineConfig({
  projectName: 'kaoyan-platform-mvp',
  date: '2026-11-15',
  designWidth: 750,
  sourceRoot: 'src',
  outputRoot: 'dist',
  framework: 'react',
  compiler: 'webpack5',
  mini: {
    postcss: {
      pxtransform: { enable: true },
      cssModules: { enable: false },
    },
  },
});
```

- [ ] **Step 2: Point WeChat DevTools at Taro output**

Change `apps/miniprogram/project.config.json` so `miniprogramRoot` is `"./dist/"`; preserve the existing project name, tourist app ID, and local-development settings.

- [ ] **Step 3: Run the static TypeScript check**

Run:

```powershell
pnpm.cmd --filter miniprogram build
```

Expected: `tsc --noEmit -p tsconfig.json` exits with code 0.

- [ ] **Step 4: Commit the configuration**

```powershell

### Task 3: Build and verify the importable mini-program bundle

**Files:**
- Modify: `README.md`
- Generated and ignored: `apps/miniprogram/dist/`

**Interfaces:**
- Consumes: `pnpm run build:weapp`, the Taro configuration from Task 2, and optional `TARO_APP_API_BASE_URL`.
- Produces: an importable `apps/miniprogram` project whose `miniprogramRoot` resolves to `dist/`.

- [ ] **Step 1: Build the WeChat bundle**

Run:

```powershell
pnpm.cmd --filter miniprogram build:weapp
```

Expected: the command exits successfully and creates these files:

```powershell
Test-Path apps/miniprogram/dist/app.js
Test-Path apps/miniprogram/dist/app.json
Test-Path apps/miniprogram/dist/pages/tasks/index.js
```

All three checks must print `True`.

- [ ] **Step 2: Verify API URL injection without changing source**

Run a second build with a temporary API URL:

```powershell
$env:TARO_APP_API_BASE_URL = 'http://127.0.0.1:3000'
pnpm.cmd --filter miniprogram build:weapp
Remove-Item Env:TARO_APP_API_BASE_URL
```

The build must still pass. The default source fallback remains `http://localhost:3000` when the variable is absent.

- [ ] **Step 3: Document local development and DevTools import**

Add this section to `README.md` after the existing local API instructions:

```markdown
### 微信小程序预览

先在一个终端启动 API：

```powershell
pnpm.cmd dev:api
```

再在另一个终端启动微信端监听构建：

```powershell
pnpm.cmd --filter miniprogram dev:weapp
```

在微信开发者工具中导入仓库的 `apps/miniprogram` 目录；项目配置会将小程序根目录指向自动生成的 `dist/`。本地 API 默认使用 `http://localhost:3000`，需要其他地址时先设置 `TARO_APP_API_BASE_URL`。

生产构建使用：

```powershell
pnpm.cmd --filter miniprogram build:weapp
```
```
